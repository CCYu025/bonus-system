# 出勤表單：請假類別鎖定、SOP表現欄位、實際產量欄寬調整

## 1. Problem Statement

出勤表單（`AttendanceForm`/`AttendanceRecord`）目前只有「出勤類別未填」一種鎖定情境——未填時同列其餘欄位（加班時數／配合度／3S表現／實際產量／備註）全部鎖定並清空。但現場實務上，事假、病假、特休這三種請假類別本質上也不該填加班時數／配合度／3S表現／實際產量（人沒到班，這些欄位沒有意義），目前系統卻允許填寫，造成資料誤植風險。同時，8/1 上線的擴充欄位（配合度／3S表現）之外，現場評分項目還需要「SOP表現」這一項，結構與既有的配合度／3S表現清單相同；而 3S表現／SOP表現這兩項評分欄位目前允許留白，實務上多數情況應預設為「正常」而非空白，減少班長逐筆手動選擇的負擔。此外實際產量欄位在目前版面上偏寬，與其單一整數欄位的定位不成比例。本次目標是把這些調整一次做完，維持既有的鎖定／清空防線設計（前後端一致、後端為唯一防線）。

## 2. Scope（本次範圍）

**In scope**
- `AttendanceCategory` 新增布林欄位標記「是否鎖定擴充欄位」，`scripts/seed.cjs` 將事假／病假／特休三筆標記為鎖定，其餘既有類別維持不鎖定
- 出勤類別為「鎖定類」時，同列加班時數／配合度／3S表現／SOP表現／實際產量鎖定為不可編輯，**備註欄位維持可編輯**
- 出勤類別的異動（切入鎖定類別）導致同列進入鎖定狀態時，將對應鎖定的欄位清空為 `null`
- 新增「SOP表現」可管理清單資料表，結構比照既有配合度／3S表現（`code/name/sortOrder/isActive`，不含分數欄位），管理介面新增第四個子分頁
- `AttendanceRecord` 新增 `sopPerformanceId` 欄位，表單填寫頁新增「SOP表現」欄位，顯示順序位於「3S表現」與「實際產量」之間
- SOP表現欄位比照既有3S表現，納入「出勤類別未填」與「出勤類別為鎖定類」兩種鎖定情境
- 3S表現、SOP表現清單各自新增一筆固定的「正常」預設選項（`scripts/seed.cjs` 塞入），該筆選項鎖定為**不可停用／編輯／刪除**；清單中其餘選項維持現行開放 CRUD（新增／編輯／排序／停用）
- 出勤表單填寫頁 3S表現、SOP表現下拉選單移除「未選」選項；當某列出勤類別由鎖定狀態（未選或請假鎖定類別）切換為可自由填寫的類別、且未另外指定這兩欄位的值時，自動預設帶入「正常」選項
- 配合度欄位不在本次調整範圍，維持允許不選（含「未選」選項）
- 「實際產量」輸入欄位寬度調整為目前寬度的一半（純視覺調整）
- （**2026-08-04 新增**）「實際產量」欄位順序移至「出勤類別」與「加班時數」之間；表格外層加橫向捲動容器；3S表現／SOP表現下拉欄位寬度限制在調整前的一半以下並截斷過長文字

**Out of scope**
- 任何評分／權重計算邏輯，包含 SOP表現清單的 `score` 欄位
- 事假／病假／特休以外類別是否要鎖定的判斷（本次僅這三類，未來調整由 `seed.cjs` 資料異動處理，不需改程式邏輯）
- 「未填」鎖定情境既有規則的重新設計（沿用 8/1 上線的規則，僅擴充涵蓋 SOP表現欄位）
- 出勤類別本身的新增／編輯功能（維持既有唯讀限制，見 `docs/database.md`）
- 既有（本次上線前）已存在、3S表現欄位為 `null` 的記錄之資料回填——維持原樣，不追溯修改
- 配合度欄位是否移除「未選」選項——本次不變動配合度的既有行為

## 3. Functional Requirements

- FR-1：`AttendanceCategory` 新增 `locksExtendedFields`（布林，預設 `false`）欄位；`scripts/seed.cjs` 將事假（`PERSONAL_LEAVE`）、病假（`SICK_LEAVE`）、特休（`ANNUAL_LEAVE`）三筆更新為 `true`，其餘既有類別維持 `false`。
- FR-2：出勤表單填寫頁中，當某列出勤類別的 `locksExtendedFields` 為 `true` 時，加班時數／配合度／3S表現／SOP表現／實際產量呈現不可編輯，備註欄位不受影響、維持可編輯。
- FR-3：當出勤類別的異動使同列**進入**鎖定狀態（無論是切為未選，或切為 `locksExtendedFields=true` 的類別）時，該列被鎖定範圍內的欄位清空為 `null`——未選情境清空全部六欄（含備註，既有規則不變）；`locksExtendedFields=true` 情境僅清空加班時數／配合度／3S表現／SOP表現／實際產量五欄，備註欄位保留原值。
- FR-4：新增「SOP表現」資料表與對應 CRUD API，結構比照 `ComplianceRating`／`ThreeSPerformance`（`code/name/sortOrder/isActive`），不含分數欄位；類別管理頁面新增第四個子分頁，操作模式（新增／編輯／排序／停用）與配合度／3S表現相同。
- FR-5：出勤表單填寫頁新增「SOP表現」下拉欄位，選項來自 SOP表現管理清單；顯示順序緊接在「3S表現」之後、「實際產量」之前。
- FR-6：後端 `saveFormRecords`（或其後續實作）的鎖定／清空規則，同時涵蓋「出勤類別未填」與「出勤類別為鎖定類（`locksExtendedFields=true`）」兩種情境，不可僅靠前端限制（沿用既有 NFR-1 精神）。
- FR-7：出勤表單填寫頁「實際產量」輸入欄位的顯示寬度調整為目前寬度的一半，不影響其資料驗證邏輯（正整數限制維持不變）。
- FR-8：`ThreeSPerformance`、`SopPerformance` 各自在 `scripts/seed.cjs` 新增一筆固定 code 的「正常」預設選項（idempotent）；此選項鎖定為不可停用／編輯／刪除（前端不提供操作入口，後端亦拒絕針對此選項的停用／編輯／刪除請求），清單中其餘選項維持現行開放 CRUD。
- FR-9：出勤表單填寫頁的 3S表現、SOP表現下拉選單移除「未選」選項，僅列出清單中目前啟用（`isActive=true`）的選項。
- FR-10：當某列出勤類別由鎖定狀態（未選或 `locksExtendedFields=true` 的請假鎖定類別）切換為非鎖定類別、且該次變更未另外指定 3S表現／SOP表現的值時，這兩欄位自動帶入各自清單中「正常」選項的 id；出勤類別仍為未填或請假鎖定狀態時，這兩欄位維持既有規則清空為 `null`（FR-3／FR-6 的鎖定清空規則優先於本預設規則）。
- FR-11：配合度欄位不在本次調整範圍，維持允許不選（保留「未選」選項），行為與調整前一致。
- FR-12：本次調整不回填既有（上線前）已存在且 3S表現為 `null` 的記錄；新的預設規則僅套用於本次上線後、使用者實際切換出勤類別（由鎖定切為非鎖定）的操作。
- FR-13（**2026-08-04 新增**）：3S表現／SOP表現的選項內容為完整敘述句，導致 `<select>` 欄寬撐開、表格整體橫向溢出可視範圍（驗收階段實測發現）。表格外層加上可橫向捲動的容器，超出視窗時以捲軸檢視，不裁切任何資料；3S表現／SOP表現兩個下拉欄位另外限制固定寬度（實測調整前分別約 334px／386px，本次限制在 150px，皆低於調整前寬度的一半），欄位顯示文字過長時以省略號截斷，並透過 `title` 屬性 hover 顯示完整內容，下拉選單展開時仍完整顯示所有選項全文。

## 4. Acceptance Criteria

AC-1：出勤類別為事假／病假／特休時，鎖定除備註外的其他欄位
- Given：某人員該列出勤類別選擇為事假、病假或特休其中之一
- When：使用者檢視或嘗試編輯該列
- Then：加班時數、配合度、3S表現、SOP表現、實際產量皆呈現不可編輯狀態；備註欄位維持可編輯

AC-2：切入鎖定類別（未選或請假類）時清空對應範圍欄位
- Given：某列出勤類別原為可自由填寫的類別（例如正常出勤），且加班時數／配合度／3S表現／SOP表現／實際產量至少一項已填值
- When：使用者將該列出勤類別改為事假／病假／特休其中之一並儲存
- Then：該列加班時數、配合度、3S表現、SOP表現、實際產量全部清空為 `null`；備註欄位的既有值不受影響、維持可編輯

AC-3：後端拒絕繞過鎖定規則的寫入（請假類情境）
- Given：某人員該列出勤類別為事假／病假／特休其中之一
- When：客戶端直接呼叫表單記錄更新 API，嘗試寫入非空的加班時數／配合度／3S表現／SOP表現／實際產量
- Then：API 拒絕該筆欄位寫入（回傳錯誤或忽略非空值，僅保留 `null`），不會被寫入資料庫；同一請求中的備註欄位寫入不受影響，可正常儲存

AC-4：SOP表現清單可管理且不含分數欄位
- Given：開發者在「SOP表現」子分頁新增一筆選項
- When：輸入 code／name 並儲存
- Then：該選項出現在出勤表單填寫頁對應的下拉清單中，且該清單資料結構不含任何分數／權重欄位

AC-5：SOP表現欄位顯示於3S表現之後（**AMENDED 2026-08-04**：實際產量欄位移至出勤類別與加班時數之間）
- Given：使用者進入出勤表單填寫頁（可編輯或唯讀檢視皆同）
- When：檢視表格欄位順序
- Then：欄位順序為出勤類別／實際產量／加班時數／配合度／3S表現／SOP表現／備註；SOP表現緊接在3S表現之後（原順序將實際產量排在SOP表現之後、備註之前，因實際產量為每日必填欄位、優先度高於加班時數等選填欄位，2026-08-04驗收階段確認改為此順序）

AC-6：3S表現、SOP表現下拉選單無「未選」選項
- Given：出勤表單填寫頁中，某列出勤類別已選且非鎖定類別
- When：開啟該列的3S表現或SOP表現下拉選單
- Then：選項僅包含清單中目前啟用（active）的各項名稱，不包含「未選」這個選項

AC-7：出勤類別由鎖定狀態切為可自由填寫類別時，3S表現／SOP表現自動預設為「正常」
- Given：某列出勤類別原為未選或請假鎖定類別（3S表現／SOP表現因鎖定規則為 `null`）
- When：使用者將該列出勤類別切換為非鎖定類別（例如正常出勤），且未另外指定3S表現／SOP表現的值
- Then：3S表現、SOP表現欄位自動帶入各自清單中「正常」選項的 id，不維持 `null`

AC-8：「正常」選項不可被停用或編輯
- Given：開發者進入3S表現或SOP表現子分頁
- When：檢視或嘗試操作清單中的「正常」這一筆選項
- Then：系統不提供停用／編輯／刪除該選項的操作入口，且後端對此選項的停用／編輯／刪除請求一律拒絕；「正常」選項固定存在且維持啟用狀態，清單中其餘選項的操作方式不受影響

AC-9：配合度欄位不受影響，維持允許不選
- Given：出勤類別已選且非鎖定類別
- When：使用者檢視配合度下拉選單
- Then：配合度選單仍包含「未選」選項，行為與本次調整前一致，不受3S表現／SOP表現規則變更影響

AC-10：SOP表現與3S表現欄位納入既有「未填」鎖定規則
- Given：某人員該列出勤類別為未選（`null`）
- When：使用者檢視或嘗試編輯該列
- Then：SOP表現、3S表現欄位與加班時數、配合度、實際產量、備註同樣呈現不可編輯狀態，且值為 `null`（不套用AC-7的「預設正常」規則，鎖定清空規則優先）

AC-11：既有舊記錄不被本次規則回填
- Given：本次功能上線前已存在、3S表現欄位為 `null` 的出勤記錄（任何狀態）
- When：本次功能上線後，使用者查詢或檢視該筆既有記錄
- Then：該記錄的3S表現欄位維持原本的 `null` 值，不因新規則被自動回填或改動

AC-12：實際產量欄位寬度改為目前一半
- Given：使用者進入出勤表單填寫頁（編輯模式）
- When：檢視實際產量輸入欄位
- Then：該欄位的顯示寬度為調整前寬度的一半（純視覺調整），資料驗證邏輯（僅接受正整數）不受影響

AC-13（**2026-08-04 新增**）：表格橫向捲動、3S表現/SOP表現欄寬限制
- Given：使用者進入出勤表單填寫頁，視窗寬度小於表格實際寬度
- When：檢視表格
- Then：表格可橫向捲動、不裁切任何欄位資料；3S表現／SOP表現下拉欄位寬度限制為調整前寬度的一半以下，內容過長時以省略號截斷並可透過 hover 或展開下拉查看完整文字

## 5. Non-Functional Requirements（NFR）

- NFR-1：鎖定／清空規則須同時涵蓋「未填」與「請假類」兩種情境，且前後端一致 — 標準：對任一鎖定情境（出勤類別為 `null` 或 `locksExtendedFields=true`）送出的任何 API 請求，若嘗試寫入非空的鎖定欄位值，後端一律拒絕或忽略，不依賴前端限制作為唯一防線（對應 AC-3）。
- NFR-2：新增欄位不影響既有資料 — 標準：`sopPerformanceId` 為可為 `null` 的欄位，`locksExtendedFields` 為布林欄位並有預設值 `false`，既有已核准／已送審表單的既有記錄可正常讀取與顯示，不需回填資料即可通過既有測試。
- NFR-3：「正常」預設選項不可被誤刪除／停用而導致預設值機制失效 — 標準：無論操作者角色為何，後端對 `ThreeSPerformance`／`SopPerformance` 中「正常」選項的停用／編輯／刪除請求一律拒絕（對應 AC-8）。

## 6. Open Questions

無（本輪討論已決議：`locksExtendedFields` 採獨立布林欄位；切入鎖定狀態時清空對應欄位為 `null`；3S表現／SOP表現的「正常」預設選項鎖定為不可停用／編輯；預設值套用時機為出勤類別由鎖定切為可填寫類別時，而非表單建立當下；既有舊資料不回填）。
