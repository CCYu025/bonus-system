# 出勤查詢頁補齊擴充欄位

## 1. Problem Statement

出勤表單自 `2026-08-01-attendance-extended-fields` 與 `2026-08-03-attendance-leave-lock-sop-field` 兩次迭代起，已支援填寫「實際產量」「加班時數」「配合度」「3S表現」「SOP表現」五個擴充欄位，且這些欄位也已經納入月分數計算（`2026-08-06-score-rules-lookup-scoring`）。但「出勤查詢」頁（`/attendance-query`）自建立以來從未同步更新，目前仍只顯示日期、工號、姓名、出勤類別、備註，開發者/使用者查詢當月出勤資料時無法看到這五個欄位的實際填寫內容，需要另外打開每一份出勤表單詳情頁才能確認，查詢頁失去其原本「快速檢視當月全貌」的作用。

## 2. Scope（本次範圍）

- **In scope**：
  - 出勤查詢頁（`/attendance-query`）表格新增顯示「實際產量」「加班時數」「配合度」「3S表現」「SOP表現」五個欄位
  - 對應的查詢 API（`queryAttendanceByMonth`）補上這五個欄位（含關聯名稱）的回傳資料
  - 表格因欄位增加，支援橫向捲動避免資料被裁切
- **Out of scope**：
  - 針對這五個新欄位新增篩選功能（沿用現有的姓名/出勤類別下拉篩選即可，不新增篩選條件）
  - 針對這五個新欄位新增小計/統計功能（既有「類別小計」維持只依出勤類別統計）
  - 變動出勤查詢既有的三層過濾邏輯（僅顯示已核准表單、僅現行版本、未填出勤類別的紀錄不顯示）——本次僅新增顯示欄位，不改變查詢結果的紀錄範圍
  - 出勤表單填寫頁（`/forms/[id]`）本身的欄位或行為變更

## 3. Functional Requirements

- **FR-1**：出勤查詢頁表格在「出勤類別」欄位之後，依序新增「實際產量」「加班時數」「配合度」「3S表現」「SOP表現」五欄，順序比照出勤表單詳情頁既有慣例。
- **FR-2**：數值型欄位（實際產量、加班時數）已填寫時顯示原始數值；未填寫（資料庫值為 null）時顯示空白，比照出勤表單詳情頁（`/forms/[id]`）既有的 `?? ""` 慣例，不顯示「未填」文字。
- **FR-3**：關聯型欄位（配合度、3S表現、SOP表現）已設定時顯示對應項目的名稱（非內部 id）；未設定（資料庫值為 null）時同樣顯示空白，比照出勤表單詳情頁既有慣例。
- **FR-4**：出勤類別本身會強制清空擴充欄位的情況（如「特休」「事假」等鎖定擴充欄位的類別），對應紀錄的這五欄與一般未填寫視為相同狀態，皆顯示空白，不額外標示原因。
- **FR-5**：查詢結果表格支援橫向捲動，欄位增加後在較窄畫面下資料不被裁切或遮蔽。

## 4. Acceptance Criteria

AC-1：查詢結果顯示已填寫的實際產量
- Given：某筆出勤紀錄的「實際產量」已填寫為正整數
- When：開發者查詢該月的出勤資料
- Then：查詢結果表格中「實際產量」欄位顯示該數值

AC-2：查詢結果顯示已填寫的加班時數
- Given：某筆出勤紀錄的「加班時數」已填寫為 1–12 之間的整數
- When：開發者查詢該月的出勤資料
- Then：查詢結果表格中「加班時數」欄位顯示該數值

AC-3：查詢結果顯示已設定的配合度
- Given：某筆出勤紀錄已設定「配合度」項目
- When：開發者查詢該月的出勤資料
- Then：查詢結果表格中「配合度」欄位顯示該項目的名稱

AC-4：查詢結果顯示已設定的3S表現
- Given：某筆出勤紀錄已設定「3S表現」項目
- When：開發者查詢該月的出勤資料
- Then：查詢結果表格中「3S表現」欄位顯示該項目的名稱

AC-5：查詢結果顯示已設定的SOP表現
- Given：某筆出勤紀錄已設定「SOP表現」項目
- When：開發者查詢該月的出勤資料
- Then：查詢結果表格中「SOP表現」欄位顯示該項目的名稱

AC-6：未填的擴充欄位顯示空白
- Given：某筆出勤紀錄的出勤類別已填寫，但實際產量、加班時數、配合度、3S表現、SOP表現皆未填寫（值為 null）——注意：出勤類別本身未填的紀錄，依查詢頁既有的 `isFilledRecord` 過濾邏輯，本來就不會出現在查詢結果中，不在本 AC 討論範圍
- When：開發者查詢該月的出勤資料
- Then：這五個欄位皆顯示空白，比照出勤表單詳情頁（`/forms/[id]`）既有的顯示方式，不顯示任何文字

AC-7：因出勤類別鎖定而被清空的擴充欄位視同未填
- Given：某筆出勤紀錄的出勤類別為會鎖定擴充欄位的類別（例如特休、事假），該五個擴充欄位因此在資料庫中被強制存為 null
- When：開發者查詢該月的出勤資料
- Then：這五個欄位顯示空白，不額外標示或區分「因類別鎖定而清空」與「使用者原本沒填」

AC-8：類別小計不受新增欄位影響
- Given：開發者在查詢頁面篩選姓名或出勤類別後得到一組結果
- When：檢視畫面下方的「類別小計」表格
- Then：小計表格仍只依「出勤類別」統計筆數，不因新增的五個欄位而新增額外的小計維度

AC-9：欄位增加後表格可橫向捲動
- Given：查詢結果表格因新增五個欄位而超出畫面寬度
- When：開發者在較窄的畫面（如筆電螢幕）檢視查詢結果
- Then：表格可橫向捲動檢視完整欄位，資料不被裁切或遮蔽

## 5. Non-Functional Requirements（NFR）

NFR-1：新增欄位不得引入 N+1 查詢問題 — 標準：`queryAttendanceByMonth` 對配合度／3S表現／SOP表現三個關聯改用 Prisma `include` 隨主查詢一次撈取，不得在迴圈中對每筆紀錄額外查詢資料庫。
