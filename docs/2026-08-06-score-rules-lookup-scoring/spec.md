# 積分規則設定擴充：配合度／3S表現／SOP表現

## 1. Problem Statement

出勤表單上的每筆紀錄都可以填寫「配合度」「3S表現」「SOP表現」三個欄位（`AttendanceRecord.complianceRatingId`／`threeSPerformanceId`／`sopPerformanceId`），這三個清單的項目也能透過「類別管理」畫面新增／改名／停用。但目前這三個欄位**完全沒有進入計分**：`/score-rules`（積分規則設定）頁面只能設定「出勤類別」與「加班」的積分，`score-query.ts` 查詢月分數時也完全不讀取這三個欄位。填了等於白填，對使用者造成落差。

本次需求：讓配合度／3S表現／SOP表現的每個項目都能個別設定積分，並讓這些積分實際併入月分數查詢結果。

## 2. Scope（本次範圍）

**In scope**：
- 「積分規則設定」頁面新增三個章節：配合度、3S表現、SOP表現，可對清單中的個別項目設定積分。
- 三個清單透過「類別管理」新增／改名的項目，即時反映在積分規則設定頁面，不需額外同步機制。
- 3S表現／SOP表現清單中標記為鎖定（`isLocked=true`）的「正常」項目，不開放設定積分。
- 已停用（`isActive=false`）的項目，在積分規則設定頁面仍顯示，標示「停用」狀態，積分唯讀不可編輯，但先前設定的積分持續生效於既有計分。
- `score-query.ts` 查詢月分數時，將這三項的積分納入計算，加總邏輯比照現行「出勤類別」的做法。
- 未設定積分的項目，計分時視為 0 分。
- 權限比照現有規則：僅 `developer` 角色可設定積分。

**Out of scope**：
- 「實際產量」（`actualQuantity`）欄位的計分——不屬於本次需求，維持現狀不計分。
- 現有「出勤類別」「加班」積分規則的行為變更（含其停用後仍在清單中消失的既有行為，本次不回頭修改）。
- 積分歷史快照／版本控制——積分沿用現行「即時套用當下規則值」的行為（修改積分會回頭影響過去月份的查詢結果），本次不引入快照機制。
- 這三個清單項目的刪除功能——目前系統本來就沒有刪除 API（只有停用），本次不新增。
- 是否將三份清單的 CRUD／積分規則程式碼抽成共用元件——屬於實作面的技術選擇，留待 `/plan` 階段決定，不在本次 spec 的功能範圍內。

## 3. Functional Requirements

- **FR-1**：開發者可在積分規則設定頁面，為「配合度」清單中的每個項目個別設定積分。
- **FR-2**：開發者可在積分規則設定頁面，為「3S表現」清單中未鎖定的項目個別設定積分。
- **FR-3**：開發者可在積分規則設定頁面，為「SOP表現」清單中未鎖定的項目個別設定積分。
- **FR-4**：積分規則設定頁面即時反映「類別管理」中對配合度／3S表現／SOP表現清單的新增、改名等異動。
- **FR-5**：3S表現／SOP表現中標記為鎖定（`isLocked=true`）的「正常」項目，不提供積分設定入口，且 API 層拒絕對其設定積分的請求。
- **FR-6**：已停用的配合度／3S表現／SOP表現項目，在積分規則設定頁面中仍顯示、標示「停用」狀態，積分欄位唯讀不可編輯；已設定的積分值持續生效於計分，重新啟用後可再編輯。
- **FR-7**：查詢月分數時，將配合度／3S表現／SOP表現的積分納入計算，加總方式與現行出勤類別積分一致。
- **FR-8**：未設定積分的配合度／3S表現／SOP表現項目，計分時視為 0 分。

## 4. Acceptance Criteria

**AC-1**：配合度項目可設定積分（FR-1）
- Given：開發者登入積分規則設定頁面，「配合度」清單中有一個項目「跨崗位」尚未設定積分
- When：開發者在「跨崗位」的積分欄位輸入一個整數並儲存
- Then：系統成功儲存該積分值；重新載入頁面後，「跨崗位」顯示剛剛設定的積分，不再顯示「未設定」

**AC-2**：3S表現「正常」項目不提供積分設定入口（FR-2, FR-5）
- Given：「3S表現」清單中「正常」項目標記為鎖定（`isLocked=true`）
- When：開發者開啟積分規則設定頁面的「3S表現」章節
- Then：「正常」這一列不顯示積分輸入欄位，不可編輯

**AC-3**：SOP表現「正常」項目不提供積分設定入口（FR-3, FR-5）
- Given：「SOP表現」清單中「正常」項目標記為鎖定（`isLocked=true`）
- When：開發者開啟積分規則設定頁面的「SOP表現」章節
- Then：「正常」這一列不顯示積分輸入欄位，不可編輯

**AC-4**：鎖定項目的積分設定在 API 層也被拒絕（FR-5）
- Given：某個 3S表現或 SOP表現項目標記為鎖定（`isLocked=true`）
- When：直接呼叫設定積分的 API，對該鎖定項目送出積分設定請求（繞過畫面）
- Then：系統回應錯誤，拒絕設定，不寫入任何積分值

**AC-5**：新增的清單項目即時出現在積分規則設定（FR-4）
- Given：「配合度」清單目前沒有「跨崗位」這個項目
- When：開發者在「類別管理」新增一個配合度項目「跨崗位」
- Then：重新載入積分規則設定頁面時，「配合度」章節顯示「跨崗位」這一列，積分欄位顯示「未設定」且可編輯

**AC-6**：改名後積分規則設定同步顯示新名稱（FR-4）
- Given：「配合度」清單中「跨崗位」已設定積分為 10 分
- When：開發者在「類別管理」將「跨崗位」改名為「跨部門支援」
- Then：重新載入積分規則設定頁面時，該列顯示名稱為「跨部門支援」，原本設定的 10 分不受影響

**AC-7**：停用項目在積分規則設定中標示「停用」且唯讀（FR-6）
- Given：「配合度」清單中「跨崗位」已設定積分為 10 分
- When：開發者在「類別管理」將「跨崗位」設為停用
- Then：積分規則設定頁面的「配合度」章節仍顯示「跨崗位」這一列，標示「停用」，積分欄位顯示 10 分但沒有輸入框或儲存按鈕

**AC-8**：停用項目的積分無法透過 API 被修改（FR-6）
- Given：「跨崗位」目前為停用狀態，積分為 10 分
- When：直接呼叫設定積分的 API，對已停用的「跨崗位」送出新的積分設定請求
- Then：系統回應錯誤，拒絕變更，原本的 10 分維持不變

**AC-9**：重新啟用後恢復可編輯且保留原積分（FR-6）
- Given：「跨崗位」先前被停用時積分為 10 分
- When：開發者在「類別管理」重新啟用「跨崗位」
- Then：積分規則設定頁面該列恢復可編輯，積分欄位顯示先前設定的 10 分，不需重新輸入

**AC-10**：月分數查詢納入三項積分（FR-7）
- Given：某人員某日的出勤紀錄中，「配合度」欄位填寫為積分 10 分的項目、「3S表現」欄位填寫為積分 5 分的項目、「SOP表現」欄位未填寫
- When：查詢該人員該月的分數
- Then：該筆紀錄的配合度積分計為 10 分、3S表現積分計為 5 分、SOP表現積分計為 0 分（因未填寫），三者皆併入該人員的月總分

**AC-11**：未設定積分的項目計為 0 分（FR-8）
- Given：「3S表現」清單中有一個項目「異常」尚未設定積分
- When：某筆出勤紀錄的「3S表現」欄位填寫為「異常」，查詢該月分數
- Then：該筆紀錄的 3S表現積分計為 0 分

## 5. Non-Functional Requirements（NFR）

- **NFR-1**：僅 `developer` 角色可設定／修改配合度、3S表現、SOP表現的積分 — 標準：非 `developer` 角色呼叫設定積分的 API，回應 403（比照現有 `category-score-rules` 與這三個清單本身 CRUD API 的權限要求）。
- **NFR-2**：積分為即時查詢當下規則值計算，不落地儲存快照 — 標準：與現行 `queryScoresByMonth` 的既有行為一致（修改積分會回頭影響已查詢過的過去月份結果），不引入版本／快照機制。

## 6. Open Questions

以下兩點已於 AC 確認前拍板，記錄供 plan 階段參考：

- **Q1（已決議）**：積分值比照現有「出勤類別」積分（`CategoryScoreRule.points`），限制為整數，不支援小數。
- **Q2（已決議）**：積分規則設定頁面新增的三個章節，排列順序接在現有「出勤類別」「加班」之後，依序為：配合度 → 3S表現 → SOP表現。
